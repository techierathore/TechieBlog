Migrating a Blazor app from Fluent UI to TrBlazeUI

Ravi Rathore ·Aug 2, 2026 ·Blazor ·9 min read
#blazor #dotnet #trblazeui #migration
featured image · 1200×630

Swapping a component library in a mature Blazor Server app sounds like the kind of project that eats a quarter. It doesn't have to. Over three weeks I moved TechieBlog from Microsoft Fluent UI Blazor to TrBlazeUI — component by component, page by page — with the app shippable at every commit. This is the field guide I wish I'd had on day one.

The trick is that both libraries render plain HTML with CSS-variable theming, so you can host them side by side during the transition. Map each Fluent control to its TrBlazeUI counterpart (FluentCard → TbCard, FluentDataGrid → TbDataTable), migrate one route at a time, and let the router decide which world a page lives in.

Theming: one token bridge, zero forked styles

Rather than restyling twice, I wrote a small bridge that projects TrBlazeUI's design tokens onto Fluent's. Dark mode is just a class toggle on the root element — TrBlazeUI's mechanism — so both libraries flip together:

// Program.cs — register TrBlazeUI alongside Fluent during migration builder.Services.AddTrBlazeUI(options => { options.Theme = TbTheme.Zinc; options.DarkModeClass = "dark"; // html.dark toggled by TbThemeToggle }); // _Imports.razor @using TrBlazeUI.Components

With the bridge in place, the remaining work is mechanical: replace markup, delete the Fluent package reference per project, and run the Playwright smoke suite after each page. The final commit removes the bridge itself — 41 lines in, 41 lines out.

Next in this series we'll tackle the interactive heavy-hitters: dialogs, toasts and the data table's server-side paging — where the two libraries disagree the most about who owns the render tree.
