## Session Parameters

- **Goal:** Compare Clone vs. Template distribution approaches
- **Audience:** .NET developers comfortable with code
- **Revenue Model:** Free, open source
- **Support Model:** "Here's the code, good luck" - minimal ongoing maintenance
- **Use Cases (all equally important):**
  1. Deploy a working blog engine immediately
  2. Starting point to build custom blog
  3. Learn Blazor best practices by studying real code

---

## Options Evaluated

### Option A: Clone & Own (GitHub Repository)
- Users fork/clone the repo
- They get the full working codebase
- They modify directly in their clone
- Updates via manual merge from upstream (or not at all)

### Option B: dotnet new Template
- NuGet package with `dotnet new` template
- Users run: `dotnet new techieblog -n MyBlog`
- Generates new project pre-configured
- No direct connection to repo after creation

## Secondary Factor Analysis

| Factor | Clone (GitHub) | dotnet new Template |
|--------|---------------|---------------------|
| Effort to create | Zero - already done | Medium - need template packaging |
| Effort to maintain | Zero | Low - keep template in sync |
| Discoverability | GitHub search, stars, SEO | NuGet.org + GitHub |
| Professional feel | Standard for OSS | More polished/official |
| User onboarding | README → Clone → Configure | `dotnet new` → familiar workflow |
| Updates for users | Git pull/merge | Re-run template (loses customizations) |

## Decision

### Recommended: Clone & Own (GitHub Repository)

**Primary reasons:**
1. **Aligns with "here's the code, good luck" philosophy** - a repo IS the code; a template implies a packaged product
2. **Zero additional effort** - repo already exists, templates require packaging + maintenance
3. **Target audience knows git** - experienced .NET devs, `git clone` is not a barrier
4. **Better for learning** - commit history shows architectural evolution
5. **Community building** - GitHub stars/forks/issues create visible traction
6. **Industry standard** - most OSS starter projects use this model

### Enhancement: GitHub Template Repository Feature

GitHub's "Template Repository" feature offers a middle ground:
- Users click "Use this template" button
- Creates a NEW repo (not a fork) with the code
- Clean git history (single initial commit)
- No upstream connection to maintain

**This is the recommended approach** - easier than `dotnet new`, cleaner than forking.
